## New

### Languages

- Mortar is open for translation on Hosted Weblate; Spanish (with Argentina and Panama variants) and Brazilian Portuguese are under way
- Settings › General › Language lists a language once part of it is translated, with how much is done; following the system language switches only to a language that is mostly translated
- The tray menu, desktop notifications, file dialogs and startup messages follow the language too
- Help translate Mortar, beside the Language setting and in the guide, opens the project on Weblate

### Linux

- Graphics in Settings › Appearance: Smoother scrolling for computers where scrolling is slow or the fans spin up in Mortar, as on some graphics cards, and Compatible for a window that stays blank

### Problems

- Every section is on one page, each with its count; Slow startup, Redundant, Cleanup, Replaced and Dismissed are links under the list
- Each problem has one button for its suggested fix, with the other fixes and Dismiss in its menu, and Why? beside it

### Faster

- Mortar starts with far less work drawing the Mods page
- Switching a mod on or off rechecks problems sooner, Load order shows dependency names without waiting, and Settings › Storage sizes the data folder in about half the time
- Searching every mod's settings on the Config page answers in a fraction of the time, most of all for BepInEx games
- Selecting a mod, opening Settings, the Console and the title bar menus do far less redrawing, and a large profile's problem check after a switch takes a fraction of the time
- The first problem check after Mortar starts takes about a quarter less time, game settings open without waiting on GitHub each time, the loader's state shows at once on start, and the Config tab's search filters once you pause typing

### Wording

- One word for each thing throughout: Enable and Disable everywhere, and "cannot" rather than "can't"
- Error messages that said the same thing in different words now use one headline
- Settings descriptions that only repeated their setting's name are gone

### Play

- **Launch options…** in the menu beside Play opens the profile's own launch arguments, command prefix and environment variables

### Mods list

- The list's columns follow each mod's own source and loader: Latest, Released, Updated, Rating and Downloads come from Nexus or Thunderstore, whichever the mod is from, and the id column shows a BepInEx plugin's GUID or a SMAPI mod's UniqueID under that name
- A mod from GitHub shows its latest release, when its installed release came out and its downloads, once Mortar has checked it for updates
- BepInEx games add Kind (plugin, patcher, library or files only) and Plugin version
- The column menu is grouped: the mod, its versions, its health, its place in the profile, then its source

### Browse

- GitHub search finds mods under every topic their authors use: Lethal Company searches five topics instead of one (338 repositories instead of 122), Stardew Valley and Vintage Story three each

## Fixed

- A problem the Console shows for a run, such as a newer copy of a mod you are building loading in place of the installed one, has Dismiss; it stays dismissed in later runs until you choose Restore
- The Console keeps your place while you read back through the log; new lines scroll it only when it is at the bottom, and dragging its scroll bar keeps up
- A Nexus download of a BepInEx or MelonLoader mod that is only its DLL installs again; it was refused as an optional file of another mod
- Add to group no longer shows "Something went wrong in this view" when the profile already has a group
- Opening a mod's details in Browse keeps that mod on screen instead of jumping to another page
- Browse's list view shows each mod's picture again; it had shrunk to a sliver under the star, which covered the name's first letter
- Importing an r2modman profile brings a mod you added to it by hand as a local mod, instead of calling it removed from Nexus with a page link that does not exist
- The What's new and sync dialogs close with Close
- Adding a mod's zip that does not say who made it installs it, by Unknown as r2modman names it, instead of refusing it
- A mod zipped inside its own folder, such as a suit pack with no DLL, installs as its package instead of asking for a mod folder
- A mod added from a file shows its own icon.png when no site gives it a picture
- A mod picture with a transparent background shows the card behind it on the Mods tab, as it does in Browse, instead of a coloured square
- Animated mod pictures (GIF, animated PNG and WebP) play instead of stopping on their first frame
- Creating a profile while Mortar is adding SMAPI's own mods to every profile no longer fails
- A controller used in another game no longer controls Mortar in the background: pressing Start to pause that game used to start the open profile's game
- The extra mods folder lists BepInEx and other Thunderstore games' mods, and a C# project's build folder as one mod, instead of asking each for a SMAPI UniqueID
- A mod added from an extra mods folder is installed again whenever its folder changes, so a mod you are building stays current in the open profile
- Importing a Vortex or Mod Organizer 2 profile for a game other than Stardew Valley names each mod from its own package or plugin instead of showing it blank
- A BepInEx or MelonLoader game no longer offers Import from the game's Mods folder, shows new folders from it on the Mods tab or watches it, which only a Stardew Valley install has
- The Cleanup list in Settings › Storage and the archive preview name BepInEx, MelonLoader and other Thunderstore mods, and group copies of one package, instead of showing them blank; the Downloads watcher names a Thunderstore zip by its package
- An archive Mortar cannot install for a BepInEx, MelonLoader or other non-Stardew game is refused with words that say what Mortar expected, instead of "No SMAPI mod was found" or a question about a SMAPI manifest
- A GitHub release installed for a BepInEx, MelonLoader or other non-Stardew game shows "Could not verify its source" in the queue, since there is no repository check for those games
- A second Nexus file for a BepInEx, MelonLoader or other non-Stardew mod already in the profile installs as its own mod instead of asking to add it to the first
- On Windows, a game that crashes stays "Running" until its process has fully closed, so its files are cleaned up and it no longer shows up as a second run of another profile
- Stop game on Windows no longer fails with "Access is denied" for a game that is already closing, and a game Windows will not let Mortar end says so instead of offering Open storage settings
