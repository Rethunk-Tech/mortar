Mortar 0.6.0 · November 8, 2026

Sign in to Nexus Mods in your browser

Nexus Mods sign-in moves to the browser, mods and Develop projects sort by hand, configs can change while you play, the Flatpak can build mods, and a list of fixes covers load order, Proton, Develop and share imports.

What changed in 0.6.0

New

  • Nexus Mods sign-in happens in your browser: choose Sign in to Nexus Mods in Settings › Accounts and approve Mortar. If a sign-in is already in progress, the button shows Cancel
  • Desktop notifications go through the system portal, and clicking one brings Mortar back to what it was about
  • The Flatpak builds mods with Flathub's .NET SDK extension, and New mod prints the install command when the extension is missing
  • Game code in Develop is offered whenever the game's install is known, with or without a mod project
  • The stream overlay for Stardew Valley adds weekday, days left, friend and pet fields
  • Develop's diagnostics zip carries each project's last build log, and mortar.log gets a line per build
  • The console's Performance panel has Stop measuring for BepInEx games; it keeps the last summary readable
  • A Sort menu beside Group by sorts the Mods list in list and card views, and Manual lets you drag mods into any order, saved per profile, with mods added later at the bottom
  • Develop's projects sort by name or by hand: drag them into your own order
  • A mod's config can be edited while the game runs. BepInEx games re-read a changed .cfg at once, so mods that react to setting changes apply it without a restart
  • On Linux, Sandbox the game (a game's Play settings) runs a directly started game inside a sandbox that keeps it to its own folders; the Console lists anything it was denied, with an Allow button
  • A share's import preview lists the changed copies of files it carries
  • Mortar says when its signed game catalog is more than 14 days old, with a retry
  • An installed Thunderstore mod shows every category the site lists for it: the Mods list's Category column adds a count beside the first, and the mod's details name them all

Changed (10)
  • Personal Nexus API keys are gone, and Mortar deletes a saved one, so sign in again once
  • Nexus Mods and GitHub request counts in Settings › Accounts say what time they reset
  • Menus follow one order: the main action first, and an ellipsis only on items that ask for more input
  • Develop names the Thunderstore team an upload goes out as, and Release everywhere says Nexus was skipped when you are not signed in
  • A package's config files are applied when you install or update it, the way r2modman and Gale do, even over another mod's settings (a theme pack's); your later edits stay, and the file it replaced is listed under Problems to restore
  • Updates install only with Mortar's signed release statement
  • SMAPI, MelonLoader and BepInEx packs install only as the signed catalog pins them; a newer release waits for the next catalog, and Settings says so
  • CurseForge and mod.io downloads are checked against the hash the site publishes, and a download address that is not https is refused
  • Sharing between your own computers over the LAN is sealed end to end, and repeated pairing attempts are limited
  • Keep mods in the game folder (a game's settings, for games whose mods go straight into its folder) leaves them in place after the game exits, so starting the game outside Mortar loads them and the next Play skips every file that has not changed

Fixed (20)
  • Games that load from a folder and have no ordering extension no longer show a broken Load order tab
  • Mortar finds a Proton prefix in any Steam library, not only the game's own
  • The Flatpak finds a .NET install in your home folder's .dotnet, and the code decompiler runs with the Flatpak's own dotnet, and the dedicated server starts with the dotnet on the host, where it runs
  • Removing a Develop project that something still holds names the programs holding the folder
  • A Build or Pack queued behind Trash refuses instead of building a project that is gone
  • Reset all in a mod's config is one restore point and one write
  • Vintage Story's mod database is fetched once an hour, not again for every page you browse
  • Mortar keeps the newest 20 startup reports per profile and deletes older ones
  • Endorse prompts are counted per game, so Never in one game no longer silences the same mod number in another
  • A failed share import is undone before its preview comes back
  • A FOMOD item is laid out in the store's own cache
  • Ticking levels under Levels shown in a game's Console settings saves again
  • The Share dialog counts every mod, and a development profile's share lists Develop's test helpers as left out, so its numbers add up
  • History records one event per change, against what it changed from
  • A long mod id wraps after its dots in the detail panel
  • Clone in Develop starts in the same projects folder as New mod
  • Screen readers announce dragged items by name in Profiles, Develop, Mods and the list's column menu
  • Scripts a mod places in the game folder (.sh, .ps1, .bat and the like) are copies, so editing one there no longer changes the stored mod, and mod files keep their executable bit on Linux
  • Load order's move buttons and note follow the whole order while the list is filtered
  • In a Manual order, a library you drag stays where you dropped it instead of moving back under the mod that needs it
