Mortar 0.4.0 · November 1, 2026

Make mods in Mortar

Develop releases to Nexus Mods and CurseForge, builds every project at once and reads the game's code with hooks to copy, Config reads settings straight from each plugin, and a list of fixes.

What changed in 0.4.0

New

  • Develop's Release uploads to Nexus Mods and CurseForge as well as Thunderstore
  • Develop can adopt any folder as a project, and a project's content is a grid of tiles (suits, sounds, posters and more) that also picks its Thunderstore categories
  • Build all builds every code project in the profile at once, each after the projects it depends on
  • Game code: right-click a name for Go to definition, Find usages, or a HookGen, MonoMod or Harmony hook to copy for a method; Side by side links each C# line to its IL
  • In the Console, the methods in an error's stack trace open Game code, with arrows to step through the trace (needs a code project in Develop)
  • Config reads a plugin's settings from its DLL: defaults and new settings show right after a rebuild, and a mod that has never run has settings to edit
  • A setting the host shares shows a crown when the host enforces it and a thumbs-up when the host only recommends it
  • Config has the Mods page's Group by
  • F5 on Browse refreshes its listings
  • Alt+Right goes forward, beside Alt+Left back
  • Gale sync links open in Mortar

Changed (3)
  • Settings merges Source health into Accounts, one block per service, and a setting a profile changed shows a dot and a reset button
  • The tab header no longer repeats the profile name the title bar shows
  • A mod that needs a newer SMAPI is listed as a problem, and a requirement whose version can't be compared shows as unknown instead of blocking Play

Fixed (14)
  • A switched-off mod's settings stay listed and editable in Config, and edits made while it is off are there when it comes back on
  • Problems no longer blames Mortar's bridge for an error the game threw
  • Game code's Side by side shows real C# instead of "Unknown result type" on every line
  • Clicking a mod in an imported profile toggles it even while text is selected
  • A Thunderstore search past its refresh waits for the new listing, and a prerelease ranks below its release
  • Programs started from the AppImage (git, dotnet, the browser) get your system's libraries, not the AppImage's
  • A Gale or r2modman local mod keeps the version and author its manager recorded
  • A folder of content files with no DLL in an extra mods folder installs as a local package
  • An error that runs only through Harmony patches is blamed on the mod whose patch threw
  • Switching a mod off and on again keeps its newest settings
  • Mod uploads from Develop never send a site's API key on to another host
  • New profile's "Start from" field and the launch preview are named for screen readers
  • Restoring a removed mods folder or old files only ever restores from Mortar's own trash
  • Combining a mod's files into another entry keeps its settings
