# Security model

What Mortar treats as untrusted input, the code that refuses it, and the test that fails if the guard goes. Reporting a vulnerability and verifying downloads: [SECURITY.md](../SECURITY.md). A path that names no top-level folder (`internal/`, `frontend/`, `web/`, `main.go`) is under `internal/`.

Mortar runs as the signed-in user with no elevated component, so every guard protects the user's own files from a crafted download, pack, link, peer or page.

Rows that name a `Fuzz*` target keep it in that package's `fuzz_test.go`. `go test` runs the seeds and minimised crashers under `testdata/fuzz/`; `go test -fuzz=FuzzX -fuzztime=2m ./internal/<package>` explores further.

| Tests touching real data | `datadir` refuses a non-temporary data folder under `go test` | `TestTestsCannotReachRealData` (`datadir`) |

## Out of scope

A malicious mod's own code runs inside the game with the user's rights; Mortar installs it where the loader expects it and does not sandbox the game. Mortar does not verify Nexus or Thunderstore content beyond the archive checks above.
