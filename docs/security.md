# Security model

What Mortar treats as untrusted input, the code that refuses it, and the test that fails if the guard goes. Reporting a vulnerability and verifying downloads: [SECURITY.md](../SECURITY.md). A package in parentheses after a test is under `internal/`.

Mortar runs as the signed-in user with no elevated component, so every guard protects the user's own files from a crafted download, pack, link, peer or page.

Rows that name a `Fuzz*` target keep it in that package's `fuzz_test.go`. `go test` runs the seeds and minimised crashers under `testdata/fuzz/`; `go test -fuzz=FuzzX -fuzztime=2m ./internal/<package>` explores further.

## Imports and extraction

Extraction stops at the first failure and leaves its output in a temp folder the caller discards.

| Antivirus scan of extracted mods: a malicious mod reaches the store and then the game folder | `internal/store/scan.go#checkExtracted` runs `avscan` inside `install`, the one place every add path (LAN receives too) passes before the store rename. | Catalog `caches`: a catalog path or symlink makes a launch delete outside the named caches | `internal/components/components.go#Validate` requires a local slash path with no `..`, backslash or leading slash under an existing role; `internal/launchsvc/caches.go#clearCache` resolves under the role folder, refuses `..`, absolute paths, symlinked parents and links, deletes only regular files and a named folder's contents, never the role folder; a failure is logged and never blocks the launch | `TestValidateChecksCachePaths` (`components`), `TestClearCacheRefusesAPathThatLeavesItsFolder` (`launchsvc`) |
| The game's `Options.ini`: the player's own file is the input; a BOM, UTF-16 or missing section would be mangled, a crash mid-swap could lose it | `internal/iniedit/iniedit.go#Set` keeps the BOM and line endings, edits only inside the named section, returns `ErrUTF16` untouched; `internal/savesiso/fileswap.go#ApplyFile` journals before moving anything and `PurgeFile`/`RecoverFile` decide each step from disk, never deleting the player's file while it is the only copy; `internal/launchsvc/pipeline.go#swapOptions` recovers an earlier journal first | `TestSetRefusesUTF16Untouched` (`iniedit`), `TestFileRecoverFromEveryKillPoint`, `TestFileRecoverAfterKillMidPurge` (`savesiso`) |
| Catalog `markerDir`: points the install check or direct start outside the install | `internal/components/components.go#Validate` accepts a slash path with no backslash, `..` or leading slash (`ServerSpec.validate` holds `configFile` to the same rule); `GameInfo.MarkerPath` is the only place it joins the marker (every store driver, `internal/game/catalog_only.go#ValidInstall`, `internal/lutris/lutris.go#rootOfMarker`) | `TestMarkerDirValidation`, `TestServerSpecsAreChecked` (`components`), `TestEAFindsAnInstallWhoseMarkerSitsInAFolderBelowTheRoot` (`gamestore`), `TestInstallFromAConfigWhoseExeIsANestedMarker` (`lutris`) |
| Report to author: a site-supplied issues link or GitHub repo name sends the window somewhere else | `internal/source/curseforge/curseforge.go#secureLink` keeps only https links without credentials; `internal/source/http.go#GitHubRepo` and `frontend/src/mods/reportToAuthor.ts#githubIssueURL` accept only `ghrepo.Valid`'s `owner/name`, and the window opens links through `opener.Web` | `TestReportTargetPrefersTheIssueTrackerOnGitHub` (`source/curseforge`), `github issue URL refuses a repo that is not owner/name` (`reportToAuthor.test.ts`) |

## Out of scope

A malicious mod's own code runs inside the game with the user's rights; Mortar installs it where the loader expects it and does not sandbox the game. Mortar does not verify Nexus or Thunderstore content beyond the archive checks above.
