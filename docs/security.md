# Security model

Untrusted input, the guard that refuses it, and the test that fails if the guard goes. Reporting a vulnerability: [SECURITY.md](../SECURITY.md). Mortar runs as the signed-in user with no elevated component, so every guard protects the user's own files from a crafted download, pack, link, peer or page.

Guards are `file#Symbol` pointers under `internal/` unless rooted elsewhere; a test's package is in parentheses (under `internal/`). A `Fuzz*` target lives in its package's `fuzz_test.go`: `go test` runs the seeds under `testdata/fuzz/`, and `go test -fuzz=FuzzX -fuzztime=2m ./internal/<package>` explores further.

## Antivirus scanners

`avscan` runs Windows AMSI, clamd over a unix socket, a custom command (no shell; `{path}` replaced by the folder; exit 0 clean, any other code a detection named by the first stdout line) or nothing. A scan that fails or times out is not a detection: the mod installs and an `avscan:failed` event says so. A file Windows blocks while Mortar writes it reaches the same refusal through `store.RealTimeBlock`, which has no Install anyway.

## Out of scope

A malicious mod's own code runs inside the game with the user's rights; Mortar installs it where the loader expects it and does not sandbox the game. Mortar does not verify Nexus or Thunderstore content beyond the archive checks above.
