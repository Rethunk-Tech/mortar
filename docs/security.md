# Security model

Untrusted input, the guard that refuses it, and the test that fails if the guard goes. Reporting a vulnerability: [SECURITY.md](../SECURITY.md). Mortar runs as the signed-in user with no elevated component, so every guard protects the user's files from a crafted download, pack, link, peer or page.

Guards are `file#Symbol` pointers under `internal/` unless rooted elsewhere; a test's package is in parentheses (also under `internal/`). A `Fuzz*` target lives in its package's `fuzz_test.go`: `go test` runs the seeds under `testdata/fuzz/`; `go test -fuzz=FuzzX -fuzztime=2m ./internal/<package>` explores further.

## Imports and extraction

Extraction stops at the first failure and leaves its output in a temp folder the caller discards.

## Antivirus scanners

Mortar's `avscan` picks the scanner the settings name; [go-avscan](https://github.com/Totative/go-avscan) runs Windows AMSI, clamd over a unix socket, a custom command (no shell; `{path}` replaced by the folder; exit 0 clean, any other code a detection named by the first stdout line) or nothing. A scan that fails, times out or meets a file over clamd's stream limit is not a detection: the mod installs and an `avscan:failed` event says so. So is a configured scanner that cannot be reached (a clamd socket that does not answer, a command that will not start): the event names it (`avscan.Config.Notice`, `TestAScannerThePlayerSetUpThatCannotBeReachedIsReported`). With no scanner set up, nothing is reported. A file Windows blocks while Mortar writes it reaches the same refusal through `store.RealTimeBlock`.

## Out of scope

A malicious mod's own code runs inside the game with the user's rights; Mortar installs it where the loader expects it and, unless the player turns on the opt-in Linux game sandbox ([design](design.md#game-sandbox-linux-opt-in)), does not sandbox the game. With the sandbox on, the game reaches D-Bus only through a filtered `xdg-dbus-proxy` (GameMode, ScreenSaver and `org.freedesktop.portal.*` names; portals can show the player a file chooser), or no session bus at all when the proxy is missing; the system bus is unreachable, and the game's process count is capped (`sandbox.Argv`, `sandbox.StartProxy`, `sandbox.TaskCap`; tests `TestArgvAlwaysSetsASessionBusAddress`, `TestProxyArgvFiltersToTheNamesGamesUse`). A mod can write any path into its log to bait an Allow click, so the Console's Allow offer and the extra-folders setting both refuse a folder that holds, contains or sits inside the player's keys and sign-ins (`~/.ssh`, `~/.gnupg`, `~/.config/gh`, browser profiles, keyrings; `sandbox.Allowable`, `sandbox.ExtraFolders`; test `TestNoFolderOfKeysOrSignInsIsOfferedOrAccepted`). Mortar does not verify Nexus or Thunderstore content beyond the archive checks above.

One Ed25519 key signs the updates, their statements, the catalog and the signed lists. The signatures cannot stand in for one another (files use ed25519ph, statements and catalogs sign different text), but one leaked key forges all of them; splitting the keys needs new secrets from the maintainer and is not done.

The single-instance handoff on Linux drops a caller whose executable is not Mortar's, but accepts one whose `/proc/<pid>/exe` cannot be read, because a Flatpak or other bus proxy reports a pid from another namespace. A same-user process can use that, and a same-user process can already reach the control channel.
