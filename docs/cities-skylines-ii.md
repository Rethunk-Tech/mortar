# Cities: Skylines II: research

Nobody on the team owns the game. Sources: PCGamingWiki's page (wikitext through its API), a decompiled 1.x Steam build in `bworthy89/roadmod` (`New folder/`), the GDK build's API dump in `ps1ke/Cities-Skylines-2-Modding-Guide`, LTT Labs' `LTTLabsOSS/markbench-tests` `games/cities_skylines_2/cities_skylines_2_utils.py`, and Steam's app info for `949230` (`api.steamcmd.net/v1/info/949230`).

- **Saves:** `{localLow}/Colossal Order/Cities Skylines II/Saves/<platform user id>/<city>.cok` with a `<city>.cok.cid` beside it (the save's content id). The folder below `Saves` is `PlatformManager.userSpecificPath`, a Steam id on Steam (`SaveGameMetadata.kPersistentLocation`, `Game.Assets/SaveGameMetadata.cs:14`; markbench's `SAVE_LOCATION`, `cities_skylines_2_utils.py:24`). The game ships only for Windows, so on Linux the path sits in the Proton prefix (`compatdata/949230/pfx`). PCGamingWiki gives the same folder for the Microsoft Store build. The catalog's `saveFiles` `*.cok`, `saveCompanions` `.cok.cid` and `saveUserFolders` encode this.
- **Where a save goes:** the save dialog lists the game's remote storages: `Local` (the folder above) and, on Steam, `SteamCloud` (`AssetDatabase<SteamCloud>`, `Game.SceneFlow/GameManager.cs:1526`) or, on the Xbox build, `GdkCloud`. The choice is remembered as `lastCloudTarget` in the `UserState` settings file in the user data folder, default `Local` (`Game.Settings/UserState.cs`). Autosaves always go to the local folder (`AutoSaveSystem.GetAutoSaveDatabaseTarget` returns `AssetDatabase.user`, `Game/AutoSaveSystem.cs:168`).
- **Cloud sync:** Steam Cloud saves are written through the Steam API into `userdata/<id>/949230/remote` (PCGamingWiki), and the app declares no Auto-Cloud paths (its `ufs` has only `quota` and `maxnumfiles`), so Steam never syncs the local `Saves` folder. Paradox account sync covers mods and playsets, not saves: its conflict dialog resolves with `PdxSdkPlatform.SyncModConflict` (`GameManager.cs:1339-1355`). So swapping the local `Saves` folder per profile cannot upload one profile's cities over another's or delete a cloud save. A city saved to Steam Cloud or the Xbox cloud stays outside the swap, shared by every profile.
- **Per-profile saves** use the shared swap ([architecture](architecture.md#saves)). The entry sets no `newProfileSeparateSaves`: a new profile would open on an empty city list, and cities run to hundreds of MB.
- **Unverified without the game:** a launch with separate saves on, under Proton and on Windows; whether **Continue** in the menu or launcher, which `UserState` points at a city in the shared folder, copes when that city is missing from the profile's folder; the Xbox build's user folder name.
